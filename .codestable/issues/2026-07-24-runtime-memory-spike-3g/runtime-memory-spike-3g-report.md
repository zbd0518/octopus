# 运行时内存冲高至约 3GB Issue Report

## 1. 问题现象

本地开发环境启动后，进程内存大致在 **40~80MB**。运行一段时间后，观察到内存可升至约 **3GB**。用户曾提到大约 **4 个请求一起** 时看到过该量级，但目前尚未系统对比「请求结束后是否回落」，也尚未整理出稳定、可重复的最小复现步骤。

本报告只记录现象与约束，不推测根因。

## 2. 复现步骤

目前**尚无稳定、可执行的最小复现步骤**。已知线索：

1. 本地启动服务，空闲内存约 40~80MB。
2. 服务运行一段时间，并处理过若干聊天/转发类请求（用户印象中曾有约 4 个请求并发）。
3. 观察到：进程内存可到约 3GB。

复现频率：**暂无法稳定**；触发条件、是否与并发数、模型、流式/非流式、上下文长度相关，均待阶段 2 进一步核实。

## 3. 期望 vs 实际

**期望行为**：空闲约 40~80MB，正常本地负载后内存仍大致保持在百 MB 级稳态，不应轻易冲到 GB 级。

**实际行为**：运行一段时间后（用户观察中与少量请求/并发相关）内存可到约 3GB，增长幅度远超预期。请求结束后是否回落、是否持续爬升，目前未确认。

## 4. 环境信息

- 涉及模块 / 功能：本地 dev 的 API 转发 / 聊天补全相关流量
- 相关文件 / 函数：待定
- 运行环境：本地 dev
- 其他上下文：
  - 启动基线约 40~80MB
  - 峰值约 3GB
  - 用户曾关联「约 4 个请求一起」
  - 请求结束后内存是否回落：未观察
  - 是否仅特定模型/渠道/流式场景：未确认

## 5. 严重程度

**P1** — 核心中继服务内存可能失控，本地已能到约 3GB，存在 OOM、卡顿与开发机资源耗尽风险，应尽快查清。

## 备注

- 路径判定：根因未定位、可能跨 relay/transformer/缓冲/日志/缓存等多模块，**不满足快速通道**，走 **standard**（report → analyze → fix）。
- 阶段 2 建议优先核实：峰值是否可复现、结束后是否回落、是否与并发/流式/大响应体相关，再定位泄漏或峰值缓冲点。
